Three Agents.

PromptWar is an OpenEnv-compatible reinforcement-learning environment where three LLM agents collaboratively edit a single contested system prompt that controls a downstream consumer chatbot — with completely different goals.

Architecture
How agents interact

Each agent has a hidden objective it's trying to optimize via edits to the shared prompt. They must negotiate within hard token budgets.

Brevity

Game Loop
Episode structure

Each episode runs 1–3 rounds (configurable by curriculum stage). Three turns per round, one per agent.

01

Reset

Episode begins with a neutral shared system prompt. All agents start fresh. Episode ID and seed are assigned.

02

Turn rotation

A → S → B → repeat. Each agent submits one edit command. Rejected edits incur no penalty but waste the turn.

03

End-of-round scoring

After every B turn, all three rubrics fire. The Consumer Model responds to sampled prompts; scores are tallied independently.

04

RL training signal

Each agent's LoRA adapter receives only its own rubric score as reward — hidden objectives stay hidden during training.

Action Grammar (§4.3)
Edit commands
Command Behavior Constraints
APPEND: <text> Appends text to the shared prompt text ≤ 80 tokens; total ≤ 500 tokens; text non-empty
DELETE: <regex> Removes first regex match valid regex; result ≥ 50 tokens; 100 ms compile timeout
REPLACE: <old> --> <new> Substitutes first occurrence new_text ≤ 80 tokens; floor & ceiling respected
PASS No-op; advances the turn Always accepted
Per-edit budget: 80 tokens
Prompt floor: 50 tokens
Prompt ceiling: 500 tokens
Tokenizer: Qwen2.5-3B-Instruct
Regex timeout: 100 ms
Curriculum (§4.7)
Three stages of difficulty
S1

Warm-up

1 round · 3 turns. Lenient grading: substring match earns half-credit on Rubric A. For early training.

S2

Standard

3 rounds · 9 turns. Normal rubric grading. Balanced negotiation between agents.

S3

Strict

3 rounds · full rubrics with anti-collusion checks. Agents must truly compete, not cooperate.
